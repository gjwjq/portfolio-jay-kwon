## 기획부터 현장 발표까지 연결해 본 경험

이음으로 사진 기반 생성, 계정 저장, 가상공간의 상호작용을 하나의 웹서비스에 연결했다. 개발 도중의 오류와 시연 준비를 거쳐 서울 데모데이에 참여했고, **Regional Top 2·$1,500 수상**이라는 결과를 얻었다.

이 경험을 웹 개발 포트폴리오로 남기는 이유는 수상뿐 아니라, 문제를 정의하고 구현·검증·사용자 피드백으로 이어 간 과정을 설명하기 위해서다. 아래 내용은 프로젝트에서 다룬 기술 범위이며, 모든 코드를 혼자 작성했다거나 공동 참가자의 역할까지 대신했다는 의미는 아니다.

| ----------- | --------------------------------------------------------------------------------- |

## 가장 크게 배운 점

### 생성 성공과 서비스 성공은 다르다

외형 파일이 만들어졌더라도 관절 연결, 움직임, 저장과 다시 열기가 이어지지 않으면 사용자는 결과를 이용할 수 없다. 각 단계의 상태와 복구 방법을 제품에 포함해야 했다.

### 행동을 연속해서 확인해야 한다

걷기만 테스트하면 보이지 않는 문제가 밥→물→놀이 전환에서 나타났다. 충돌 후 위치만 복원하고 자세를 남기는 등 작은 상태 불일치가 반복 회전과 이동 정체로 이어졌다.

### 직접 본 문제를 구체적으로 설명해야 한다

‘부자연스럽다’에서 한 단계 더 나아가, 어디서 시작해 어느 버튼을 누르면 어떤 방향으로 움직이는지 전달해야 원인을 좁힐 수 있었다. AI를 쓰는 과정에서도 화면 관찰과 재현 절차가 중요했다.

### 수상 이후에도 실제 사용자를 기준으로 개선해야 한다

샘플에서 통과한 동작이 새 보호자의 모델에서는 실패했다. 현장 수상과 모델 호환성의 완성은 서로 다른 문제였다. 실패한 실험을 제외하고 남은 범위를 기록하는 태도가 필요했다.

## 2026년 10월 21일 기준 남은 과제

- 모든 생성 체형에서의 해부학적 자연스러움과 안정적인 앉기·걷기·점프.
- 실제 Android·iPhone 하드웨어에서의 성능과 터치·동작 품질.
- 실제 운영 계정의 전체 생성·저장·재로그인·재열기 흐름.
- 공급자 리깅 실패 뒤 실제 유료 재시도의 성공 여부.
- 생성 이미지와 원본 반려동물의 닮은 정도에 대한 보호자 확인.
- 장기 사용 편의와 서비스 유지 비용, 실패 시 사용자 안내의 지속적인 개선.

단위 검사 통과, 실제 모델 일부 확인, 운영 정적 코드 배포만으로 위 과제를 전부 완료했다고 판단하지 않는다. 이음이 이별의 슬픔을 덜고 추억을 이어가는 데 도움이 되기를 바라지만, 의학적 치료 효과를 입증한 서비스로 표현하지 않는다.

## 앞으로 쌓고 싶은 경험

사용자가 직접 하기 어려운 일을 웹에서 연결하는 개발을 계속하고 싶다. 이음에서는 생성과 3D를 다뤘고, 다음 프로젝트에서도 API·데이터·화면·배포를 실제 사용 흐름으로 완성하는 경험을 쌓고자 한다.
