## 1. 클라우드 서비스 종류

클라우드는 **내 컴퓨터가 아니라 인터넷상의 서버 자원을 빌려 쓰는 것**임.

## IaaS

`Infrastructure as a Service`

인프라를 빌려주는 서비스.

```
서버
스토리지
네트워크
가상 머신
```

예시:

```
AWS EC2
Google Compute Engine
Azure Virtual Machines
```

### 암기

**IaaS = 컴퓨터/서버 자체를 빌림**

---

## PaaS

`Platform as a Service`

개발 플랫폼을 빌려주는 서비스.

개발자는 서버 관리보다 코드 작성에 집중함.

예시:

```
Google App Engine
Heroku
Vercel
Firebase
```

### 암기

**PaaS = 개발하고 실행할 판을 빌림**

---

## SaaS

`Software as a Service`

소프트웨어를 인터넷으로 사용하는 서비스.

예시:

```
Google Docs
Gmail
Notion
Slack
Microsoft 365
```

### 암기

**SaaS = 완성된 프로그램을 인터넷으로 사용**

---

## HaaS

`Hardware as a Service`

하드웨어를 서비스처럼 빌려 쓰는 형태임.

시험에서는 클라우드 서비스 종류로 나올 수 있음.

### 암기

**HaaS = 하드웨어를 빌려 씀**

---

## 클라우드 서비스가 아닌 것

다음은 일반적으로 클라우드 서비스가 아님.

```
내 컴퓨터에 직접 설치한 한글/엑셀
USB에 저장한 파일
학교 컴퓨터실에만 있는 내부 서버
인터넷 연결 없이 혼자 쓰는 프로그램
```

### 핵심 구분

**인터넷으로 서버/플랫폼/소프트웨어를 빌려 쓰면 클라우드
내 컴퓨터에 직접 설치해서 혼자 쓰면 보통 클라우드 아님**

## 2. 정보보안 개념 및 3요소

### 정보보안

정보보안은 **정보를 허락되지 않은 접근, 변경, 파괴, 유출로부터 보호하는 것**임.

### 정보보안 3요소: CIA

| 요소 | 영어 | 의미 |
| --- | --- | --- |
| 기밀성 | Confidentiality | 허가된 사람만 볼 수 있어야 함 |
| 무결성 | Integrity | 정보가 함부로 바뀌면 안 됨 |
| 가용성 | Availability | 필요할 때 사용할 수 있어야 함 |

### 예시

| 상황 | 해당 요소 |
| --- | --- |
| 비밀번호로 접근 제한 | 기밀성 |
| 성적 데이터가 조작되지 않음 | 무결성 |
| 서버가 장애 없이 접속됨 | 가용성 |

### 암기

**보안 3요소 = 기밀성, 무결성, 가용성**

## 3. 패킷 방식과 패킷 설명

### 패킷이란?

패킷은 **데이터를 작은 조각으로 나눈 것**임.

큰 파일을 한 덩어리로 보내는 게 아니라, 여러 조각으로 나눠서 보냄.

```
큰 데이터 → 패킷1 + 패킷2 + 패킷3 + 패킷4
```

각 패킷에는 보통 이런 정보가 들어감.

```
출발지 주소
목적지 주소
순서 번호
실제 데이터 조각
```

---

## 패킷 교환 방식 특징

### 핵심

**데이터를 패킷 단위로 쪼개서 여러 경로로 전송할 수 있는 방식**임.

### 특징

| 특징 | 설명 |
| --- | --- |
| 회선 독점 안 함 | 하나의 통신선을 계속 점유하지 않음 |
| 효율적 | 여러 사용자가 네트워크를 함께 사용 가능 |
| 경로 다양 | 패킷마다 다른 경로로 갈 수 있음 |
| 순서 재조립 필요 | 도착 후 순서를 맞춰야 함 |
| 인터넷에서 사용 | 현대 인터넷 통신의 기본 방식 |

### 회선 교환과 비교

| 구분 | 회선 교환 | 패킷 교환 |
| --- | --- | --- |
| 방식 | 통신 전용 회선 확보 | 데이터를 조각내어 전송 |
| 예시 | 옛날 전화망 | 인터넷 |
| 장점 | 안정적 | 효율적 |
| 단점 | 회선 낭비 가능 | 지연, 순서 변경 가능 |

### 암기

**패킷 방식 = 데이터를 작은 조각으로 나눠 보내고, 도착하면 다시 합침**

## 4. 네트워크 토폴로지: 성형 구조

문제에서:

> 중앙 장치를 중심으로 각 노드가 개별적으로 연결되는 구조
> 

이건 **성형 토폴로지**, 영어로 **Star Topology**임.

### 구조

```
      PC1
       |
PC2 - 허브/스위치 - PC3
       |
      PC4
```

중앙에 허브나 스위치가 있고, 각 컴퓨터가 중앙 장치에 따로 연결됨.

### 장점

| 장점 | 설명 |
| --- | --- |
| 관리 쉬움 | 중앙 장치 기준으로 관리 |
| 고장 찾기 쉬움 | 어느 노드 문제인지 찾기 쉬움 |
| 한 노드 고장 영향 적음 | 한 컴퓨터 고장은 전체에 영향 적음 |

### 단점

| 단점 | 설명 |
| --- | --- |
| 중앙 장치 고장 시 전체 영향 | 허브/스위치가 죽으면 전체 네트워크 문제 |
| 케이블 많이 필요 | 각 노드가 중앙까지 연결되어야 함 |

### 암기

**중앙 장치 중심 = 성형 = 스타형**

## 5. NAT의 주요 기능

NAT는 `Network Address Translation`의 약자임.

뜻은 **네트워크 주소 변환**임.

### 핵심

NAT는 **사설 IP를 공인 IP로 바꿔서 인터넷에 나가게 해주는 기능**임.

집에서 여러 기기가 인터넷을 써도 공유기 하나로 되는 이유가 NAT 때문임.

```
내 폰: 192.168.0.2
내 노트북: 192.168.0.3
내 태블릿: 192.168.0.4

→ 공유기 NAT

공인 IP 하나로 인터넷 접속
```

### 주요 기능

| 기능 | 설명 |
| --- | --- |
| 주소 변환 | 사설 IP ↔ 공인 IP 변환 |
| IP 절약 | 공인 IP 하나를 여러 기기가 공유 |
| 내부망 보호 | 내부 사설 IP가 외부에 직접 노출되지 않음 |
| 인터넷 접속 지원 | 내부 기기가 외부 인터넷 사용 가능 |

### 암기

**NAT = 사설 IP를 공인 IP로 바꿔 인터넷에 나가게 해줌**

## 6. SQL LIKE 연산자에서 `%` 역할

### 핵심

`LIKE`는 문자열 패턴 검색에 사용함.

`%`는 **글자 수 상관없이 아무 문자열**을 의미함.

```
SELECT*
FROM 학생
WHERE 이름LIKE'김%';
```

뜻:

**이름이 김으로 시작하는 사람**

예시:

```
김철수
김민지
김준
```

---

```
SELECT*
FROM 학생
WHERE 이름LIKE'%수';
```

뜻:

**이름이 수로 끝나는 사람**

예시:

```
철수
민수
현수
```

---

```
SELECT*
FROM 학생
WHERE 이름LIKE'%철%';
```

뜻:

**이름에 철이 포함된 사람**

예시:

```
김철수
이철민
박민철
```

### `%`와 `_` 차이

| 기호 | 의미 |
| --- | --- |
| `%` | 글자 수 상관없는 문자열 |
| `_` | 딱 한 글자 |

### 암기

**LIKE에서 `%` = 아무 글자 여러 개 가능**

## 7. 디지털 서명의 주요 목적

### 핵심

디지털 서명은 **전자 문서가 진짜 보낸 사람이 보낸 것이고, 중간에 변조되지 않았음을 확인하는 기술**임.

### 주요 목적

| 목적 | 설명 |
| --- | --- |
| 인증 | 누가 보냈는지 확인 |
| 무결성 | 내용이 변조되지 않았는지 확인 |
| 부인 방지 | 보낸 사람이 나중에 안 보냈다고 못 하게 함 |

### 주의

디지털 서명의 핵심은 **암호화해서 숨기는 것**이 아님.

숨기는 건 주로 **기밀성**이고, 디지털 서명은 주로:

```
인증
무결성
부인 방지
```

쪽임.

### 암기

**디지털 서명 = 누가 보냈는지 + 변조 안 됐는지 + 발뺌 못 하게**
